## Abstract

ZyenLang 0.3 is an intentionally incompatible language revision. It separates
data from identity, replaces general source-level pointers with checked local
references, gives all managed values one cleanup model, and gives names a
single unambiguous path grammar. The first backend remains portable C11, but
the checked program is represented by a backend-neutral typed IR.

There is no v0.2 compatibility mode. A compiler must diagnose old forms and
show the corresponding v0.3 spelling where one exists.

## Modules and member access

Every `.zy` file is one module. Imports are rooted and aliased:

```zy
import std::io as io
import crate::model as model
import utils::text as text
```

Only `std::`, `crate::`, and a direct dependency alias may begin an import.
`crate::net::http` maps to `src/net/http.zy`. String imports, `<std/...>`,
wildcards, selective imports, re-exports, path traversal, and implicit aliases
are forbidden.

`::` resolves module names, type names, and static methods. `.` resolves an
instance field or class method. Therefore `io::print()`, `model::Point`,
`File::open()`, `file.close()`, and `point.x` are valid categories, while
`io.print()` and `model.Point` are errors.

## Struct and class

A `struct` is a pure data value type. Its body may contain fields only. It may
not contain `fn`, `mut fn`, `static fn`, `init`, or `deinit`.

```zy
public struct Point {
    public x: i32
    public y: i32
    private label: str = "point"
}
```

Fields default to private. The declaring module can access private fields;
other modules can access public fields only. Construction uses a field literal.
Omitted fields use their declaration default or the type's zero value. Pure
Copy structs copy directly. A struct containing a managed value has generated
recursive copy and cleanup operations. Recursive by-value layouts are errors.

Behavior for data values is expressed as module functions. Identity and
encapsulation use ARC classes:

```zy
public class Cache<T> {
    private value: T

    public init(value: T) {
        this.value = value
    }

    public fn get() T {
        return CLONE__(this.value)
    }

    public mut fn set(value: T) void {
        this.value = value
    }

    public static fn identity(value: T) T {
        return value
    }

    deinit {
    }
}
```

Class construction calls `init`: `Cache<i32>(10)`. Generic class arguments are
explicit. Readonly `fn` cannot mutate `this` or transitively call a mutable
method; `mut fn` can. `static fn` receives no `this`. `deinit` takes no
arguments, cannot throw, and runs only after the final atomic ARC owner is
released. There is no inheritance, implicit subtype, variance, weak reference,
or cycle collector.

Generic functions and classes use reachable monomorphization. Generic
operations must type-check for every concrete specialization that is reached.
There are no generic constraints or method-level extra type parameters in 0.3.

## Values, strings, and lists

Numeric types are `i8/i16/i32/i64`, `u8/u16/u32/u64`, `isize/usize`, and
`f32/f64`. Mixed numeric operations promote to a common representable type.
`bool`, `void`, `Error`, tuples, and `T | null` complete the core value model.
A successful null check narrows an optional to `T` inside its branch.

`str` is immutable ARC-owned UTF-8. Character length, indexing, and slicing
operate on Unicode scalar values; byte length is a separate operation.

`List<T>` is a strongly typed managed container. Copies share an atomic ARC
backing buffer until the first mutation, which detaches through copy-on-write.
Managed elements are retained and released recursively. List may appear in a
struct or class field. Its canonical intrinsic operations are
`LIST_LEN__()`, `LIST_GET__()`, `LIST_SET__()`, `LIST_PUSH__()`,
`LIST_POP__()`, and `LIST_CLEAR__()`.

All compiler intrinsics use the `NAME__()` form with parentheses.

## Function values and closures

A function value type is written `fn(P...) R`. Values may be passed, returned,
stored in managed fields, captured, used as callbacks, and called through any
typed expression. Chained calls such as `pick("add")(20, 22)` evaluate the
callee and each argument exactly once.

Named functions, closures, and native callbacks use one logical value:

```text
{ call, env, owner, signature }
```

A named function has no environment owner. A closure captures a readonly
snapshot in an atomic ARC environment. Captured managed values are retained
and recursively released. Function signatures are invariant and exact; there
is no function-to-raw-pointer cast.

## References and ownership

Safe source references are local borrows:

```zy
let value: i32 = 10
let read: &i32 = &value
let copied: i32 = CLONE_REF__(read)
let write: &mut i32 = &mut value
REF_SET__(write, 20)
```

Multiple `&T` readers may coexist. `&mut T` is unique and excludes every other
borrow or owner access for its lifetime. References cannot be null or nested.
In 0.3 they may occur only as locals and function parameters; they cannot be
returned, captured, stored in aggregates, or kept across threads. The compiler
must reject provable dangling references and alias violations.

`CLONE__(value)` performs the value's normal clone: ARC types retain, structs
copy recursively, and List retains its COW buffer. Assignment and return obey
the same typed ownership operations.

`DROP__(local)` performs normal cleanup early and marks that binding
uninitialized. Reading, borrowing, or dropping it again is an error until an
assignment reinitializes it. Primitive values, references, and resource-free
Copy structs cannot be dropped explicitly. `FREE__()` and `SKIP__()` do not
exist.

`defer` registers a non-throwing function or class-method call. Receiver and
arguments are evaluated once at registration. Calls execute in LIFO order on
normal block exit, `return`, `break`, `continue`, catch/recover, and error
propagation. The same cleanup planner handles automatic ARC, strings, Lists,
closures, classes, structs, Drop, and defer.

## Errors and concurrency

The error forms remain `throws Error`, `stop`, `catch err`, and
`recover value`. Recovery must produce the original expression type; a void
expression uses value-less `recover`. `Error` carries message, source file,
line, column, and function stack frames. An unhandled error is printed in red
and exits without bypassing planned cleanup. A destructor or deferred call may
not introduce a second throwing path.

`spawn call()` creates an OS-backed `Task<T>` and `await task` consumes it
exactly once. Atomic ARC makes ownership counts safe between threads; it does
not make captured mutable payloads data-race safe.

## Compiler architecture

The normative pipeline is:

```text
Lexer/Parser
-> Module Graph and SymbolPath Resolver
-> Typed AST/IR
-> Generic Validation and Monomorphization
-> Borrow/Ownership Analysis
-> Cleanup Planning
-> C Backend
-> Artifact Builder
```

The checker and backend consume the same typed expression results. The typed
IR may not contain C source fragments as its semantic representation. This
keeps a future LLVM backend possible without changing source semantics.

## Safety boundary

Atomic ARC prevents premature release of ordinary owned values but cannot
collect cycles. The local borrow system is intentionally smaller than Rust's
full lifetime system. Native code and unsafe compatibility wrappers can break
all language guarantees and remain part of the application's trusted code.
